# D1 盘点与恢复清单（2026-10-29）

## 结论

不是存储满，也不是 Broker 的 Vault 库损坏。当前看到的是 **D1 每日行读取配额** 错误；数据本身仍在。

- 报错原文：`Your account has exceeded D1's free tier daily row read limit... wait until tomorrow (midnight UTC)`。
- 免费额度按 **UTC 00:00** 重置，即 **北京时间 08:00**。
- `VAULT_DB`（`secrets-broker-v2`）仍可查询：25 条条目，库 73.7 KB。
- 报错的是旧库 `NODEWARDEN_DB`（`nodewarden-db`），2.53 MB；它不是 Vault 2.0 的主库。
- 账号内 24h 行读取最高的是 `otsmail`（约 108.6 万行），Broker 的 Vault 库约 8.4 万行，不是主要消耗者。

## 明天 08:00 后按顺序做

1. 确认恢复（只读）：
   ```powershell
   npx wrangler d1 execute secrets-broker-v2 --remote --command "SELECT COUNT(*) FROM vault_items"
   npx wrangler d1 execute nodewarden-db --remote --command "SELECT COUNT(*) FROM sqlite_master"
   npx wrangler d1 info nodewarden-db
   ```
   如果 `nodewarden-db` 仍报行读取超限，不要删库；先确认是否是账号总额度或旧库单独触发，再决定升级/等待/工单。

2. 记录 schema 和关键计数，不导出密文内容：
   ```powershell
   npx wrangler d1 execute secrets-broker-v2 --remote --json --command "SELECT name, sql FROM sqlite_master WHERE type='table'"
   npx wrangler d1 execute secrets-broker-v2 --remote --json --command "SELECT COUNT(*) AS n FROM vault_items"
   ```

3. 真正备份（恢复配额后）：
   ```powershell
   npx wrangler d1 export secrets-broker-v2 --remote --output .\backup\secrets-broker-v2.sql
   npx wrangler d1 export nodewarden-db --remote --output .\backup\nodewarden-db.sql
   ```
   先确认 `backup/` 已加入 `.gitignore`；不要把导出文件提交。

4. 恢复后优先做读削减（以下为候选改动，尚未改代码/部署）：
   - `/api/me` 不再调用 `vault2Context()` 读 D1；未解锁状态从 `v2-key` Durable Object 读取。
   - `vault2Status()` 合并 `meta` 查询，去掉重复的 `vault2HasPasswordKeyring()` 查询。
   - 给 `/api/v2/status` 加短 TTL 缓存，避免页面每次刷新都读 4 次 D1。
   - 保留 `vault_items(revision)` 索引；`vault2List` 按 `since` 增量拉取，不要每次 `since=0`。

5. 账号层面：
   - `otsmail` 是当前 24h 最大 D1 读取者（约 108 万行/天）。如果账号经常触顶，优先查 `otsmail` 的轮询/全表查询，或升级 Workers Paid。
   - Broker 自身的 D1 日读取不到 10 万行，单靠 Broker 不会打满 5M 行/天。

## 不要做

- 不要因为“满了”删除 `vault_items`、`keyrings`、`devices` 或 `audit_v2`。
- 不要在配额未恢复时反复跑全表 `SELECT`；每次失败查询也可能计入统计。
- 不要把 D1 导出文件或 token 提交到 git。
